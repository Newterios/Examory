**Why JML/MAP with person parameters under adaptive selection.** Santa chooses items using the learner's previous responses (including other parts and other skills). Given theta_i, those responses carry no further information about the Part-5 responses (local independence), so item selection is ignorable when theta_i is conditioned on as a parameter; the likelihood used here is exactly that conditional likelihood. A marginal (MML) fit with one N(0,1) population would instead be misspecified, because the persons who receive an item are selected on information correlated with theta that is not in the Part-5 likelihood. Remaining biases: (i) JML incidental-parameter bias for persons with few responses (corrected to first order by the parametric bootstrap above); (ii) MAP shrinkage of theta_hat (the latent scale is pinned instead of the estimate scale); (iii) selection concentrates each item on a narrow theta range, so a and c are weakly identified for many items and lean on the priors; (iv) unidimensionality and a common c are assumptions.

## Pool retention (export rule)

An item is exported to `items` only if its bias-corrected a >= 0.25 and |b| <= 4.0. With a < 0.25 the ICC is almost flat, so b is not identified (the fit slides along the a*b ridge to |b| far beyond the population range); |b| > 4.0 lies outside the theta range the data inform. This data-quality rule was fixed before any detector result on calibrated data was seen (it was added because the Go simulator range-checks b in [-10, 10] and the dropped items are unidentified anyway). Dropped items stay in the fit, so person, time and practice-gain estimates are unchanged; `item_prior` is computed from the retained pool only.
